# Решение кейса «Карточка товара за три минуты»

## Проблема
При подготовке карточек товаров продавец вручную переписывает сведения с упаковки, загружает изображения и проверяет обязательные поля. Это занимает время, а ошибки в тексте и пропущенные характеристики ведут к повторной проверке.

## Идея
**Фермер.Карточка** — локальный MVP, преобразующий фото упаковки и исходные факты в редактируемый черновик. Ключевой принцип: **сомнительное распознавание не становится фактом**. Человек принимает итоговое решение.

## Пользовательский путь
1. **Фото** — загрузка фото и выделение участка этикетки; режим OCR («состав» / «название»).
2. **OCR** — три прохода обработки, уверенность, отбрасывание шумовых строк. Не удалось распознать — понятное предупреждение и ручной ввод.
3. **Характеристики** — извлечение веса и строк с явными префиксами «Состав», «Изготовитель», ручная проверка и правка.
4. **Готовность** — показатель заполненности 0–100; список обязательных полей; предупреждение о формате веса.
5. **Предпросмотр** — описание, список характеристик, отметка ручного подтверждения и экспорт JSON.

Цель сценария — **около трёх минут**; хронометраж на пользователях в MVP не проводился.

## Проверка требований

| Запрос кейса | Реализация / статус |
|---|---|
| Редактируемый черновик | Да, локальный UI с ручной правкой |
| Распознавание русского состава | Да, `Tesseract.js rus` и фильтры; ограниченная точность на стилизованных этикетках |
| Классификация | Нет обученной модели категории; категория вводится человеком |
| Без выдуманных фактов | Да, OCR не дополняется предположениями; состав/производитель извлекаются из подписанных строк |
| Оценка готовности | Да, базовая заполненность 4 полей |
| Рекомендации по тексту/фото | Частично: подсказки к съёмке и ручной правке; автоматического quality score фото нет |
| Предварительная модерация | Да, базовая локальная; не модерация маркетплейса |
| Недостающая информация | Да, обязательные незаполненные поля |
| API / техконтракт | Проект REST API: `docs/API_CONTRACT.md`; backend отсутствует |

## Почему такой подход
Агрессивное «исправление» неразборчивого текста может привести к выдуманным ингредиентам. Поэтому при неуверенном распознавании система предпочитает показать «текст не обнаружен», чем заполнить карточку неверными сведениями. Уверенность OCR отражает оценку модели, **а не доказанную достоверность товара**.

## Развитие
Автоматическая оценка качества фото и нескольких ракурсов; классификация категории с явным уровнем доверия; связь значений с фрагментами фото; OCR следующего поколения; серверный API, история согласований и правила маркетплейсов.
